# Design Story: From Purchase to Practice

The former site felt like several products sharing a coach’s name. The landing page spoke in restrained black and gold, onboarding used a second interpretation of that brand, and the richer dashboard prototypes switched to a generic blue-and-purple SaaS language. More importantly, those surfaces did not share a reliable data journey.

The redesign uses the customer journey as its spine. The polished public site remains the invitation. Stripe owns payment. Onboarding appears only after a server verifies a completed checkout, then saves one canonical profile and intake. The client portal turns that record into daily practice: what to train, how to eat, what to report, and where to ask for help. Coach OS shows the same system from the other side, organizing decisions by who needs attention.

Visually, the system borrows the strongest part of the existing brand—near-black space, warm gold, confident editorial hierarchy—and makes it operational. Cabinet Grotesk supplies personality without sacrificing scanning. DM Sans carries forms and dense data. Gold marks priority; it no longer decorates every surface. Borders create quiet structure while cards are reserved for meaningful groupings.

The mobile client experience uses four core destinations and a More sheet because clients return frequently and usually for one quick task. Coach OS uses a full drawer because its information architecture is broader and compressing it into a bottom bar would hide important work. Both patterns remove the duplicate navigation and horizontal overflow found in the prototypes.

Finally, the interface admits what it knows. Fictional preview data is named. Missing credentials produce a configuration state. Empty tables explain what will populate them. A sent, saved, or published message appears only after the server confirms it. That honesty is the most important part of the aesthetic: premium software should feel composed because its underlying state is trustworthy.
